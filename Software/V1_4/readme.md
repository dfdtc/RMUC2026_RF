本项目包含：
    TX：模拟发射代码
    包含数据组包，空口包生成，GFSK调制发射，射频参数需要自行调整，bw和可以freq可以推送，但其中的access code因为block的限制，无法推送修改，也没有做幅度推送（TODO）（已经设置好protocol format，只需在formatter里面改一下对象就行了）

  （Tips：本部分暂未测试，谨慎使用）

    RX：接收解调相关代码
        其中包含使用预制的GFSK Demod模块完成的解调流，以及自行完整实现的fm解调到时钟恢复（预制GFSK demod在流图中被disable掉了，需要可以打开来，如果找不到请检查是否hide disable blocks）

        以及zmq_decoder.py，这个模块接收GNURadio解调来自流图的zmq publish信息，并解码输出信息（Tips，需要重写output_result函数实现自定义的输出操作，目前仅为print结果；且这个脚本虽然设计为通用解码，但是仅测试了干扰波密码帧解码，谨慎推广使用）

    Tools：可调用的交互式工具
        如波源参数分发工具para_distro，不过RX数据帧解析的脚本在~/RX里面

    Lab： 一些测试的代码
        里面的test_ssb_fm是一个测试流图，设计计划通过滤波器过滤掉干扰源的两个符号和广播源与干扰源相邻的符号，只接收广播源离干扰较远端符号，将2GFSK退化为一个OOK来接收，模拟流里面还可以用，但是实际流不太能解调，很考验信噪比。

    decode_lib：数据帧解码工具库
        但是目前没引用到，仅供技术参考，相关代码在zmq_decoder里面有更适合流处理的实现


用法：
    解码相关代码的参数可以经由~/tools/para_distro.py进行分发，该脚本直接运行为一个测试性质的数据分发系统，初始化为蓝方波源列表，每隔15秒对干扰源参数进行升级，最后关闭参数分发，你也可以恢复被注释的CLI param接收系统。

    其设计使用方法，应该是import其中的类，并在您的雷达决策代码中调用，初始化ParaDistro类需要填入队伍颜色，其会导入JSON存储的波源参数，并根据指定的队伍颜色选择相关波源列表，接下来初始化一个zmq publisher并bind一个地址和端口；调用send_parameters（inter_level）将会将本方广播源和所选本方干扰源的波源参数推送出去一次；或者配置Auto_Distributor，start之后，它会自动连续推送所选广播源和干扰源信息，通过update_inter_level进行干扰源等级更改。

    目前解调程序还是需要分为两个代码，分别接收干扰源和广播源，不过仅参数不同（zmq接收模块配置为“boardcast”或者“inter”，可以选择本模块是接收广播源还是干扰源的参数）；

    注意需要设置plutosdr的地址，默认使用file source对预先录制的基带采样信号进行本地测试解调，plutosdr需要去enable一下那个plutosdr source；filesink设计为接收解调并repack之后的字节流，如果不需要留存用于分析则可以disable。

    如果搞不明白zmq分发工具，您也可以复制一大堆副本，然把里面的参数修改为相关每种干扰源和广播源的参数，这套系统在脱离zmq分发主机的情况下会保持“cent_freq”, "bw", "access_code"变量初始值

    解码程序是rx里面的zmq_decoder.py，这个模块接收GNURadio解调来自流图的zmq publish信息，并解码输出信息（Tips，需要重写output_result函数实现自定义的输出操作，目前仅为print结果；且这个脚本虽然设计为通用解码，但是仅测试了干扰波密码帧解码，谨慎推广使用）
